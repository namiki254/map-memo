# map-memo

地図にピンを立ててメモを残すアプリ．NTTデータ内定者ハッカソン（2026年8月）の制作物．

## 何を作るのか

普通の地図アプリと違う点は2つあります．

**1つ目．「地図」は実際の地図だけではありません．** 好きな画像をアップロードすれば，それがそのまま地図になります．ゲーム内のマップ，商業施設のフロアマップ，イベント会場の見取り図，手描きの地図．どれでもピンを立てられます．

**2つ目．地図の中に地図を入れられます．** 全国地図にピンを立て，そのピンを開くと大阪の地図が出て，そこのピンを開くと自分でアップロードしたショッピングモールのフロアマップが出る．この入れ子に深さの制限はありません．

この2つを組み合わせると，「日本地図から始めて，最終的に建物の3階の店舗前まで潜っていく」という体験が作れます．

さらに，立てたピンに日付と訪問順を持たせることで，同じデータを3つの見方で表示します．地図としての見方，旅行の日程表としての見方，そして訪問後の旅行記としての見方です．計画と記録を別々に入力する必要がありません．

### Googleマイマップとの違い

任意の画像を地図にできること，そして地図を無限に入れ子にできること．この2点はGoogleマイマップにはできません．

## 技術構成

- TypeScript / Vite / React
- Tailwind CSS
- React Router
- Supabase（データベース・認証・画像保管）
- Vercel（ホスティング）

## セットアップ

Node.js は 22系（LTS）を使ってください．パッケージマネージャは npm に統一します．

```
npm install
```

```
npm run dev
```

`http://localhost:5173` が開いて「地図（未実装）」というグレーの箱が表示されれば成功です．

Supabase に繋ぐ段階になったら，`.env.example` をコピーして `.env.local` を作り，値を埋めてください．値は Slack で共有します．

詳しい手順とつまずきどころは [docs/セットアップ手順.md](docs/セットアップ手順.md) にあります．**環境を一から作る人は必ずそちらを読んでください．** Tailwind の設定方法と Vite 特有の環境変数の書き方に，AI が古い情報を出してくる罠があります．

## ディレクトリ構成と担当

```
src/
  types.ts                  共通：勝手に変更しない．変えるときは必ず相談
  lib/supabase.ts           共通：接続設定
  components/MapView.tsx    A：地図本体
  components/PinPanel.tsx   B：ピンの作成・編集・削除
  pages/MapManager.tsx      C：画像アップロードと地図の管理
  pages/PlanView.tsx        D：計画ビュー（日程表）
  pages/DiaryView.tsx       E：旅行記ビュー
```

B・C・D・E は地図のコードを読まずに作業できます．A が詰まっても全体は止まりません．

ページを追加したら `src/main.tsx` の `<Routes>` に `<Route>` を1行足してください．1行の追加なら，同じファイルを触っても衝突はほぼ起きません．

## データ構造

テーブルは `maps` `pins` `photos` の3つだけです．型定義は [src/types.ts](src/types.ts) にあります．

**座標は `x` と `y` の数値2つで表します．** 実地図も画像地図も画面上は平面なので，実地図なら経度と緯度を，画像地図ならピクセル座標を，同じ列に入れます．地図の種類でテーブルを分けません．

**計画と旅行記でテーブルを分けません．** `pins.planned_date` が入っていれば計画，`visited_at` が入っていれば訪問済みとして扱います．同じ1件のデータを3つのビューで見せる構造です．ここがこのアプリの設計の核なので，崩さないでください．

**プロパティ名はスネークケース（`image_url`）で統一しています．** TypeScript の習慣とは違いますが，データベースの列名と1文字ずつ一致させることで変換処理を不要にしています．

## 開発上の注意

パッケージを追加したら Slack で共有してください．他の人は `git pull` の後に `npm install` が必要になります．

`package-lock.json` は必ずコミットします．

`.env.local` はコミットしません．`.gitignore` の `*.local` で除外済みです．

Supabase の `service_role`（secret）キーは，どこにも書かないでください．全権限を持つ鍵です．クライアントで使うのは anon（publishable）キーだけです．

**Supabase は1週間アクセスがないとプロジェクトが自動停止します．** お盆期間中，週1回は誰かが開いてください．

Windows と Mac が混在しています．シェルスクリプトやパス区切り文字に依存した処理は書かないでください．
