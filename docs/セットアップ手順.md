# 地図×メモアプリ セットアップ手順

最終更新：2026年8月11日

## この文書について

**手順1から5までは既に実行済みで，結果はこのリポジトリに入っています．** リポジトリを clone した人は `npm install` を実行するだけで開発を始められます．

この文書を読む場面は次の3つです．環境を一から作り直したいとき．なぜこの設定になっているのかを知りたいとき．そして，動かなくて詰まったとき（末尾のチェックリストを見てください）．

手順6以降（Supabase と Vercel）はまだ実行していません．こちらは上から順に実行してください．

**地図の表示部分はこの手順に含めません．** 地図ライブラリの選定がまだ確定していないためです．地図に依存するのは `MapView.tsx` の1ファイルだけなので，そこを仮実装にしておけば，残りの作業は全て並行して進められます．選定が決まり次第，このファイルの中身だけを差し替えます．

## 技術構成

- 言語：TypeScript
- ビルドツール：Vite
- UIライブラリ：React
- スタイル：Tailwind CSS
- ルーティング：React Router
- データベースと認証と画像保管：Supabase
- ホスティング：Vercel

サーバー側のコードは書きません．ブラウザから直接Supabaseを呼びます．「このコードはサーバーとブラウザのどちらで動いているのか」を考える必要がない構成です．

## 0. 前提を揃える

WindowsとMacが混在するので，最初にNodeのバージョンを揃えます．**Node 22系（LTS）**を使ってください．

## 2. Tailwind CSS を入れる

**ここが最初の罠です．** Tailwindはバージョンによって設定方法が全く違い，AIに聞くと高い確率で古い手順を出してきます．

具体的には，`npx tailwindcss init -p` を実行して `tailwind.config.js` の `content` 配列にパスを書く，という手順を提案されたら，それは旧バージョンの手順です．今は不要どころか動きません．設定ファイルは作りません．

正しい手順は次の3つだけです．

### 2-1. インストール

```
npm install tailwindcss @tailwindcss/vite
```

### 2-2. `vite.config.ts` にプラグインを追加

```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
})
```

### 2-3. `src/index.css` の中身を全部消して1行だけにする

```css
@import "tailwindcss";
```

### 確認

`src/App.tsx` の中身を次に置き換えて，青くて大きい文字が出れば成功です．

```tsx
export default function App() {
  return <h1 className="text-3xl font-bold text-blue-600">Tailwind が効いています</h1>;
}
```

## 3. React Router を入れる

担当ごとに別のページを作るので，ルーティングを先に用意します．これがないと全員が `App.tsx` を編集することになり，衝突します．

```
npm install react-router-dom
```

`src/main.tsx` を次のようにします．

```tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { BrowserRouter, Routes, Route } from "react-router-dom";
import "./index.css";
import App from "./App";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<App />} />
      </Routes>
    </BrowserRouter>
  </StrictMode>
);
```

各担当は，自分のページができたらここに `<Route>` を1行足すだけにします．1行の追加なら，同じファイルを触っても衝突がほぼ起きません．

## 4. 型定義を決める

**この手順が一番重要です．** ここが揺れると全員のコードが同時に壊れます．逆にここさえ固定すれば，地図の担当以外は独立して作業できます．

`src/types.ts` を作ります．

```ts
export type MapType = "geo" | "image";

/** 地図．実地図（geo）と画像地図（image）の両方をこの型で表す */
export type MapDoc = {
  id: string;
  name: string;
  type: MapType;
  image_url: string | null;  // type が "image" のときだけ入る
  width: number | null;      // 画像の幅（ピクセル）
  height: number | null;     // 画像の高さ（ピクセル）
  owner_id: string | null;
  created_at: string;
};

export type PinKind = "note" | "link";

/** ピン．メモを持つ note と，下位の地図へ潜る link の2種類 */
export type Pin = {
  id: string;
  map_id: string;
  x: number;  // geo なら経度，image ならピクセルのX座標
  y: number;  // geo なら緯度，image ならピクセルのY座標
  title: string;
  body: string;
  kind: PinKind;
  child_map_id: string | null;   // kind が "link" のときだけ入る
  planned_date: string | null;   // "2026-08-30" 形式．入っていれば「計画」
  order_index: number;           // 同じ日の中での訪問順
  visited_at: string | null;     // 入っていれば「訪問済み」
};

export type Photo = {
  id: string;
  pin_id: string;
  url: string;
  caption: string;
};
```

### 設計上の要点が3つあります

**1つ目．座標は `x` と `y` の数値2つだけです．** 実地図も画像地図も，画面上は平面です．実地図なら経度と緯度，画像地図ならピクセル座標を同じ列に入れます．地図の種類ごとにテーブルを分ける必要はありません．

**2つ目．計画と旅行記でテーブルを分けません．** `planned_date` が入っていれば計画，`visited_at` が入っていれば記録として扱います．同じピンのデータを，地図・日程表・旅行記という3つの見せ方で表示します．これがこのアプリの構造上の核です．

**3つ目．プロパティ名はスネークケース（`image_url` のような書き方）にしています．** TypeScriptの習慣ではキャメルケース（`imageUrl`）ですが，データベースの列名と1文字ずつ一致させることを優先しました．変換処理を挟まなくて済むので，「保存したのに読めない」という原因の分かりにくいバグを丸ごと回避できます．

## 5. 地図部分の仮実装を置く

`src/components/MapView.tsx` を作ります．中身は空の箱です．

```tsx
import type { MapDoc, Pin } from "../types";

type Props = {
  map: MapDoc;
  pins: Pin[];
  onPinClick?: (pin: Pin) => void;
  onMapClick?: (x: number, y: number) => void;
};

export function MapView({ map, pins }: Props) {
  return (
    <div className="h-full w-full bg-slate-200 grid place-items-center text-slate-500">
      <div className="text-center">
        <p>地図（未実装）</p>
        <p className="text-sm">{map.name} / {map.type} / ピン {pins.length} 件</p>
      </div>
    </div>
  );
}
```

**受け渡しの形（Props）だけは今のうちに確定させます．** 地図ライブラリが決まったら，このファイルの中身だけを書き換えます．他の担当は `<MapView map={...} pins={...} />` と書いておけばよく，差し替えの影響を受けません．

## 6. Supabase に繋ぐ

Supabaseのプロジェクトを誰のアカウントで作るかがまだ未確定です．**決まるまでこの手順6は保留で構いません．** 手順1から5までは今日中に全員が終えられます．

### 6-1. インストール

```
npm install @supabase/supabase-js
```

### 6-2. 環境変数を置く

プロジェクトのルートに `.env.local` を作ります．

```
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxx
```

URLの末尾にスラッシュが付いていても動くようにしてありますが，付けない方が無難です．

**Vite特有の注意が2つあります．**

環境変数の名前は必ず `VITE_` で始めてください．この接頭辞がないとコードから読み出せません．そして読み出しは `process.env` ではなく `import.meta.env` です．AIが `NEXT_PUBLIC_` や `process.env` を使ったコードを出してきたら，それはNext.js用の書き方で，この構成では動きません．

`VITE_` を付けた値はビルド時にコードへ埋め込まれ，ブラウザから見えます．これは正常です．publishableキーは公開される前提で設計されていて，アクセス制御はデータベース側（RLS）で行います．

**ただし，`sb_secret_` で始まる secret キーは絶対にここへ書かないでください．** これは全ての権限を持つ鍵で，漏れると誰でもデータを消せます．

なお，Supabaseはキーの呼び方を新しくしている途中です．古い記事に出てくる「anonキー」が今の「publishableキー」，「service_roleキー」が今の「secretキー」に当たります．管理画面の表示がどちらでも，役割は同じです．

### 6-3. クライアントを作る

`src/lib/supabase.ts` を作ります．

```ts
import { createClient } from "@supabase/supabase-js";

// 末尾のスラッシュは取り除く．管理画面からコピーすると付いてくることがある．
const url = import.meta.env.VITE_SUPABASE_URL?.replace(/\/+$/, "");
const key = import.meta.env.VITE_SUPABASE_PUBLISHABLE_KEY;

if (!url || !key) {
  throw new Error("Supabaseの環境変数が未設定です．.env.local を確認してください．");
}

export const supabase = createClient(url, key);
```

この `throw` は必ず入れてください．設定漏れは，これがないと「なぜかデータが取れない」という原因を特定しにくい形で表面化します．

### 6-4. 秘密情報をコミットしない

`.env.local` はGitに入れません．Viteの既定の `.gitignore` に `*.local` という行があるので既に除外されていますが，念のため確認してください．

代わりに `.env.example` を作ってコミットします．新しく環境を作る人が，何を設定すべきか分かります．

```
VITE_SUPABASE_URL=
VITE_SUPABASE_PUBLISHABLE_KEY=
```

## 7. Vercel に載せる

GitHubにリポジトリを作ってpushし，Vercelの管理画面から Import します．Viteは自動判別されるので，ビルドコマンド（`npm run build`）と出力先（`dist`）は触らなくて大丈夫です．

やることは2つです．

### 7-1. 環境変数を登録する

Vercelの管理画面で `VITE_SUPABASE_URL` と `VITE_SUPABASE_PUBLISHABLE_KEY` を設定します．

**環境変数を変更したら，必ず再デプロイしてください．** Viteはビルド時に値をコードへ埋め込むため，設定を変えただけでは反映されません．

### 7-2. `vercel.json` を置く

プロジェクトのルートに作ります．

```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

これがないと，`/map/123` のようなURLを直接開いたときやページをリロードしたときに404になります．発表でURLを共有したときに踏む事故なので，先に入れておきます．

## 9. ファイル分担

```
src/
  types.ts                    共通：最初に全員で確定させ，以降は勝手に変えない
  lib/supabase.ts             共通：1人が作ったら以降触らない
  components/MapView.tsx      A：地図本体（ライブラリ選定後に着手）
  components/PinPanel.tsx     B：ピンの作成・編集・削除と詳細パネル
  pages/MapManager.tsx        C：画像アップロードと地図の管理画面
  pages/PlanView.tsx          D：計画ビュー．日付ごとのリストと並び替え
  pages/DiaryView.tsx         E：旅行記ビューとトップページ
```

B・C・D・Eは地図のコードを一切読まずに作業できます．Aが詰まっても全体は止まりません．

## 付録：詰まったときのチェックリスト

**Tailwindのクラスが効かない**
`vite.config.ts` にプラグインを追加したか．`index.css` に `@import "tailwindcss";` があるか．`tailwind.config.js` を作ってしまっていないか．設定を変えた後は開発サーバーを再起動する．

**Supabaseからデータが取れない**
環境変数名が `VITE_` で始まっているか．`import.meta.env` で読んでいるか．`.env.local` を作った後に開発サーバーを再起動したか（再起動しないと読み込まれません）．

**Vercelでは動くのにローカルで動かない，またはその逆**
ほぼ環境変数の設定漏れです．両方に同じ値が入っているか確認する．

**他の人の環境で動かない**
`npm install` を実行したか．Nodeのバージョンが22系か．

**AIが提案したコードが動かない**
Next.js用の書き方（`process.env`，`NEXT_PUBLIC_`，`"use client"`，`dynamic import`）が混ざっていないか確認する．この構成ではどれも使いません．Tailwindの設定ファイルを作る手順を提案された場合も，それは古い手順です．
